# Dashboard Guide & Architecture

## 1. Overview
The Trading Dashboard is an **Analysis & Observation Center** designed exclusively to monitor and validate the Telegram trading bot's strategies. It provides a read-only, unified interface for strategy benchmarking, market analysis, signal tracking, and paper forward-testing.

**IMPORTANT:** The dashboard does **NOT** execute live trades or connect to broker APIs. It is strictly a research and observation layer.

## 2. Architecture
The system uses a loosely-coupled multi-tier architecture:
- **Telegram Bot (`main.py`)**: The core alerting and signal engine.
- **FastAPI Dashboard API (`dashboard_api/`)**: Exposes SQLite data and analysis routes securely.
- **Next.js Frontend (`web_dashboard/`)**: High-performance UI using shadcn/ui and Tailwind CSS.
- **Strategy Registry (`strategies/registry.py`)**: Central source of truth for strategy metadata and readiness.
- **Strategy Router (`strategies/strategy_router.py`)**: Routes analysis/backtest requests to real Python adapters.
- **SMC Component Library (`strategies/smc_components.py`)**: Reusable mechanical logic for Smart Money Concepts.

## 3. Current Dashboard Capabilities
- **Real-time Market Analysis**: Multi-timeframe candlestick charts with volume.
- **Mechanical Backtesting**: High-fidelity historical simulation with no lookahead bias.
- **Forward Testing Engine**: Virtual paper-trading sessions to track live strategy performance.
- **Strategy Lab**: Central hub for batch testing and ranking all implemented algorithms.
- **Signal Tracking**: Historical log of all signals generated by the system.
- **Performance Metrics**: Comprehensive stats (Win Rate, Profit Factor, Sharpe, Drawdown).

## 4. Strategy Lab
The Strategy Lab is the core of our research framework. It allows you to:
- **Batch Run Backtests**: Simultaneously evaluate every implemented strategy on historical data.
- **Monitor Paper Performance**: Start virtual sessions to see how strategies perform in live conditions.
- **Transparency**: Every trade in the lab is logged with its exact entry, exit, stop-loss, and take-profit levels.

## 5. Forward Testing Engine
The Forward Testing Engine allows for **simulated execution** on live market data:
- **Paper Only**: No real capital is ever at risk.
- **Session Based**: Group multiple strategies into a single observation session.
- **Verification**: Used to confirm that a strategy's edge persists in current market conditions.
- **Status**: Sessions start in `PENDING_MONITORING` until the tracking daemon captures the first live signal.

## 6. Backtest Result Format
All strategy adapters return a standardized JSON schema:
```json
{
  "strategy_id": "...",
  "symbol": "...",
  "trades": [
    {
      "entry_time": "...",
      "exit_time": "...",
      "direction": "BUY/SELL",
      "entry_price": 0.0,
      "exit_price": 0.0,
      "pnl": 0.0,
      "result": "WIN/LOSS"
    }
  ],
  "equity_curve": [...],
  "metrics": {
    "win_rate": 0.0,
    "profit_factor": 0.0,
    "max_drawdown": 0.0
  }
}
```

## 7. Safety Boundaries
Strict adherence to these boundaries is mandatory:
- **No live trading**: The system lacks any connectivity to brokerage execution APIs.
- **No EA execution**: Strategies cannot be exported to MetaTrader or other external platforms.
- **No broker API**: All data is fetched from public sources (yfinance).
- **Forward test is paper only**: All "trades" in the forward testing engine are virtual entries in a database.
- **Backtest uses historical data only**: No "future" data is available during simulation (No Lookahead Bias).
- **Not financial advice**: All outputs are for research and educational purposes only.
- **No fake results rule**: Strategy status "implemented" requires a functioning Python adapter. Hardcoded or mocked signals are forbidden.

## 8. How to Add a New Strategy Adapter
1. **Create logic**: Build the strategy in `strategies/new_strategy.py`.
2. **Implement Backtest**: Add a function `run_new_strategy_backtest` that returns the standard schema.
3. **Register**: Add the metadata to `strategies/registry.py`.
4. **Route**: Map the ID to your adapter in `strategies/strategy_router.py`.
5. **Verify**: Run the validation commands listed below.

## 9. How to Verify Results
- **Console Logs**: Check the backend logs for signal generation events.
- **Database Audit**: Directly inspect `backtest_trades` or `forward_test_trades` in the SQLite DB.
- **UI Markers**: Use the Market Analysis page to visually confirm that entry/exit points align with technical levels.

## 10. Run Commands

### Backend (API)
```bash
python -m uvicorn dashboard_api.app:app --host 127.0.0.1 --port 8000 --reload
```

### Frontend (Dashboard)
```bash
cd web_dashboard
npm run dev
```

### Telegram Bot
```bash
python main.py
```

### Validation
```bash
# Verify Python syntax
python -m compileall .

# Verify Dashboard production build
cd web_dashboard
npm run build
```

## 11. Troubleshooting
- **Module not found**: Ensure `pip install -r requirements.txt` was successful.
- **CORS Errors**: Check `DASHBOARD_ALLOWED_ORIGINS` in your `.env`.
- **Database Locked**: SQLite is in WAL mode, but concurrent heavy writes from the bot may cause brief delays.
- **Empty Charts**: Verify your internet connection and ensure `yfinance` is not blocked.
